用 POM + 数据驱动重构登录脚本

2026-10-09 约 10 分钟 Selenium · pytest · Allure

我写的第一版登录自动化脚本长这样：打开浏览器、找元素、输入账号、点登录、断言标题，一共 40 行， 全部塞在一个函数里。它能跑通，但只维持了两周 —— 前端把「登录」按钮的 id 从 btnLogin 改成了 login-submit，脚本挂了 17 个用例。

这次故障让我认真学了 POM（Page Object Model）。这篇记录我从「能跑的脚本」到「能维护的框架」的改造过程， 代码基于 ECSHOP 电商后台的登录流程。

一、问题出在哪

把脚本摊开看，其实混了三件不同的事：

  • 页面定位：元素怎么找 —— 这部分最容易变，前端一改就崩；
  • 业务动作：输入账号、点登录 —— 相对稳定；
  • 测试逻辑：断言什么、跑哪些数据 —— 最稳定，也最该被复用。

POM 的本质就是把「易变的部分」关进一个类里，让测试用例只依赖业务动作，不依赖选择器。

二、三层结构

改造后的目录是这样，每一层职责单一：

ecshop-ui-test/
├── base/
│   └── base_page.py        # 公共操作：等待、点击、输入、截图
├── pages/
│   └── login_page.py       # 登录页：定位器 + 业务动作
├── data/
│   └── login_cases.yaml    # 数据驱动：用例数据
├── tests/
│   └── test_login.py       # 用例：只写断言
├── conftest.py             # fixture：浏览器启停、失败截图
└── pytest.ini              # 标记、报告参数

1. BasePage：把等待和异常收在一处

显式等待是 UI 自动化最容易被忽略的部分。早期的我做的是 time.sleep(2)， 网速快时白等、网速慢时还不够。改成统一封装： 

from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC


class BasePage:
    def __init__(self, driver, timeout=10):
        self.driver = driver
        self.wait = WebDriverWait(driver, timeout)

    def find(self, locator):
        # 统一走显式等待，元素可见才返回
        return self.wait.until(EC.visibility_of_element_located(locator))

    def click(self, locator):
        self.wait.until(EC.element_to_be_clickable(locator)).click()

    def type(self, locator, text):
        el = self.find(locator)
        el.clear()
        el.send_keys(text)

    def text_of(self, locator):
        return self.find(locator).text

2. LoginPage：选择器只出现在这里

from selenium.webdriver.common.by import By
from base.base_page import BasePage


class LoginPage(BasePage):
    # 定位器集中管理，前端改版只改这一处
    USERNAME = (By.NAME, "username")
    PASSWORD = (By.NAME, "password")
    SUBMIT = (By.CSS_SELECTOR, "input[type='submit']")
    TIP = (By.CSS_SELECTOR, ".error-tip")

    def open(self, base_url):
        self.driver.get(f"{base_url}/admin/privilege.php?act=login")
        return self

    def login(self, username, password):
        self.type(self.USERNAME, username)
        self.type(self.PASSWORD, password)
        self.click(self.SUBMIT)
        return self

    def error_tip(self):
        return self.text_of(self.TIP)

三、数据驱动：用例只写一遍

登录的正向用例只有一条，异常用例却有一堆：密码错、账号为空、账号不存在、验证码错。 如果每种情况复制一个 test 函数，后面加一条数据就要加一个函数。用 pytest.mark.parametrize 可以压成一条： 

import pytest
import yaml
from pages.login_page import LoginPage


def load_cases():
    with open("data/login_cases.yaml", encoding="utf-8") as f:
        return yaml.safe_load(f)["cases"]


@pytest.mark.parametrize("case", load_cases(), ids=lambda c: c["name"])
def test_login(driver, base_url, case):
    page = LoginPage(driver).open(base_url)
    page.login(case["username"], case["password"])

    if case["expect"] == "success":
        assert "管理首页" in driver.title
    else:
        assert case["msg"] in page.error_tip()

数据文件与代码分离，产品经理改一条文案，我只改 YAML，不碰 Python：

cases:
  - name: 正常登录
    username: admin
    password: "123456"
    expect: success
  - name: 密码错误
    username: admin
    password: "wrong"
    expect: fail
    msg: 用户名或密码错误
  - name: 账号为空
    username: ""
    password: "123456"
    expect: fail
    msg: 用户名不能为空

四、fixture：浏览器只开一次，失败自动截图

conftest.py 是 pytest 的共享夹具文件。我把浏览器启停、基础地址、失败截图都放进去， 用例里就只剩 driver 这个参数： 

import pytest
from selenium import webdriver


@pytest.fixture(scope="session")
def driver():
    d = webdriver.Chrome()
    d.implicitly_wait(5)
    yield d
    d.quit()


@pytest.fixture
def base_url():
    return "http://localhost:8080"


@pytest.hookimpl(hookwrapper=True)
def pytest_runtest_makereport(item, call):
    # 用例失败时自动截图，附到 Allure 报告里
    outcome = yield
    report = outcome.get_result()
    if report.when == "call" and report.failed:
        driver = item.funcargs.get("driver")
        if driver:
            png = driver.get_screenshot_as_png()
            try:
                import allure
                allure.attach(png, name="失败截图",
                              attachment_type=allure.attachment_type.PNG)
            except ImportError:
                pass
⚠️
踩过的坑：scope="session" 的 driver 会被所有用例复用，一旦某条用例把浏览器搞崩， 后面全部报错。我的做法是给「需要干净环境」的用例单独加一个 function 级 driver， 或者在 pytest.ini 里加 --reruns 1 兜住偶发失败。

五、报告与执行

最后用 Allure 出报告。执行命令固定成脚本，谁都能一键跑： 

pytest tests/ -m smoke --alluredir=report/allure
allure serve report/allure

报告里有通过率、失败截图、每步耗时。改造前后最直观的对比是：一次完整登录回归从 人工点击约 20 分钟，变成脚本执行 2 分钟出头， 而且失败时不用再猜「刚才点的是哪个按钮」—— 截图直接写明。

六、这套结构带来的三个改变

  1. 维护成本下降：选择器只出现在 pages/，前端改版时改动范围可控；
  2. 用例可读：测试函数里看不到 By.XPATH，只有 login()、error_tip() 这种业务语言；
  3. 能分层跑：用 -m smoke 只跑冒烟，用 -m regression 跑全量，适配不同阶段。

现在回头看，POM 不是为了「显得专业」，而是为了让自动化测试真正能被别人接手 —— 一个只有作者看得懂的脚本，价值约等于零。
